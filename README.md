# LINK — связь двух версий одной книги

Однофайловое веб-приложение (PWA). LINK — это связь: две версии одной книги, перевод и оригинал или два издания. На экране всегда одна. Вторая не стоит рядом колонкой — она связана с первой по выделенному отрывку. Рядом с чтением — ИИ-помощник: вопрос по содержанию или выделенному отрывку, поиск соответствующего места во обеих версиях и короткое «Ранее в книге» вместо пересказа всего прочитанного. Трудные места можно оставить в конспекте «Материалы». Работает целиком в браузере. Файлы книг остаются на устройстве; на сервер уходит только явно выделенный текст и только по нажатию конкретной ИИ-кнопки.

**Онлайн-версия:** https://ilsoft-dev.github.io/LINK/

---

## Предыстория

LINK не задумывался как отдельный продукт — он вырос из конкретной практической задачи: удобно прочитать одну книгу.

**1. «Кто идёт?»** (`Who_is_it.html`)
Всё начиналось с повести Джона У. Кэмпбелла «Who Goes There?» («Кто идёт?») — того самого текста, что лёг в основу фильма «Нечто». Первая версия была самой обычной read-only HTML-страницей под одну конкретную книгу: текст вшит прямо в файл, минимальная вёрстка, и главная фишка — глоссарий: непонятные слова и обороты снабжены всплывающими подсказками с переводом/пояснением прямо по тексту.

**2. День/ночь** (`Who_is_it_day_night.html`)
Следующий шаг — переключатель светлой/тёмной темы для комфортного чтения вечером. Сама концепция «книга внутри HTML-файла с глоссарием» осталась прежней.

**3. Первый настоящий «читательский движок»** (`index-1.html`)
Дальше версия под ту же книгу разрослась в полноценную читалку: закладки, синтез речи (Web Speech API) для чтения вслух, ИИ-комментарии через Groq API, тёмная тема, свой глоссарий — но всё ещё **жёстко привязано к одному тексту**: сама книга была зашита в файл, поменять её без правки кода было нельзя.

**4. Идея обобщить: рождение LINK**
Возник закономерный вопрос: а зачем привязываться к одной книге, если движок для чтения (закладки, TTS, тема, ИИ-подсказки) уже универсален? Так появился LINK — то же самое читательское ядро, но без вшитого текста: пользователь сам загружает файл(ы), какие хочет. Имя — про связь двух версий одной книги. Второй файл необязателен (оригинал или другое издание): выделив отрывок, можно найти соответствующее место во второй версии и сверить. Это не чтение «на двух языках сразу» и не две колонки.

**5. От одной книги к библиотеке**
LINK продолжил расти как самостоятельный проект: разбор `.fb2`/`.txt`, затем `.epub` и `.zip`-архивы, затем `.pdf` и `.docx`/`.html`. Появилась «Моя полка» — персистентное хранилище нескольких книг в IndexedDB с автосохранением прогресса чтения, PWA-манифест и service worker для установки на экран и офлайн-запуска оболочки приложения.

**6. Уход от прямого Groq и переработка интерфейса**
Выяснилось, что Groq API геоблокирует Беларусь — прямой запрос из браузера требовал VPN. Решением стал OpenRouter как основной провайдер (бесплатные модели, без карты, без VPN) плюс собственный relay-сервер (модуль в уже существующем Telegram-боте на Render) как запасной путь к Groq — тоже без VPN, ключ пользователя передаётся в теле запроса, а не хранится на сервере. Параллельно интерфейс получил ощутимую переработку: подписанные иконки вместо голых, панель «Оформление» с тонкой настройкой типографики, единая панель «Ассистент» вместо разбросанных кнопок, третья тема — monochrome ink под e-ink-экраны. Позже оба провайдера переведены на один и тот же relay: прямой запрос к OpenRouter из Беларуси тоже не доходил.

Итог: из одноразовой странички под конкретную повесть получился универсальный читатель, не привязанный к одному тексту, со связью двух версий одной книги и ИИ-инструментами — тот, что описан ниже.

## Возможности

- **Два режима загрузки.** «Читать» — одна версия. «LINK» — две версии одной книги (текст на экране + вторая: оригинал или другое издание), со свапом файлов местами (⇄). Файлы не показываются рядом двумя колонками: на экране одна версия, вторая связана с ней по выделенному отрывку — кнопка «Оригинал» ищет соответствующее место во втором файле.
- **Поддерживаемые форматы:** `.txt`, `.fb2`, `.epub`, `.pdf`, `.docx`, `.html`/`.htm`, а также `.zip`-архив с любым из этих форматов внутри (не только `.txt`/`.fb2`).
- **Автоопределение кодировки** для `.txt`/`.fb2`/`.html`: сначала строгий UTF-8, при неудаче — автоматический откат на windows-1251 (частая кодировка старых русских текстовых файлов).
- **Разбиение на главы** — по заголовкам `<title>`/`h1-h4`/стилям `HeadingN` там, где формат это позволяет (FB2, EPUB, DOCX, HTML — включая случай, когда вся книга лежит в одном файле, а главы обозначены только заголовками внутри него), либо по regex-паттерну «Глава/Часть/Chapter/Part» для голого текста (TXT и текст, извлечённый из PDF).
- **Оглавление** — выезжающая панель с быстрым переходом по главам и статусом главы: не начата, процент прочитанного или дочитана.
- **Поиск по книге** — лупа в верхней панели, без сети и без ИИ. Ищет в тексте на экране; в режиме LINK — ещё и во второй версии. Совпадение из второго файла открывается в окне, страница не листается. В одном абзаце показывается первое вхождение.
- **Закладки** — по абзацам, с панелью со списком, переходом и подтверждением перед удалением записей с полки.
- **Прогресс чтения** — восстанавливается на последней позиции при повторном открытии книги, включая сохранение при сворачивании приложения (не только по явному выходу «Назад»).
- **«Моя полка»** — до 15 книг одновременно (LRU: при превышении лимита вытесняется книга, которую дольше всего не открывали), файлы книг лежат в IndexedDB. Ключ книги — хэш по содержимому текста (устойчивый к небольшим расхождениям в разбиении на абзацы), а не по имени файла — один и тот же текст, загруженный напрямую или из другого контейнера, не создаёт дубликат.
- **Экспорт и импорт полки** — JSON с книгами, закладками, материалами, списком незакрытого для «Ранее» и прогрессом. Импорт только добавляет: свои книги не затираются и не вытесняются, прогресс берётся как максимум, карточки материалов сливаются по абзацу и своё поле не затирается чужим. В файле лежит уже разобранный полный текст книг, не только названия; «Поделиться» отправляет этот JSON в выбранное приложение (Telegram, почта, диск). Ключи ИИ в экспорт не входят.
- **«Материалы по книге»** — конспект трудных мест, не режим чтения. Одна карточка на абзац: цитата и то, что к ней оставили — свою заметку, комментарий, вопрос с ответом, цитату из второй версии. Пустые поля не показываются. В карточку ничего не пишется само: после ответа модели есть «Оставить здесь» и «Закрыть»; если место уже занято, старое и новое показываются рядом и выбор за читателем. На абзаце маленькая метка рядом с кружком закладки. Список открывается из верхней панели, по главам, в порядке книги; кнопки нет, пока карточек нет. Не больше 80 карточек на книгу, лишние сами не удаляются. Вопрос из панели «Ассистент» в материалы не попадает: у него нет места в тексте.
- **Три темы** — светлая (тёплые, кремовые тона), тёмная и monochrome ink (чёрно-белая, под e-ink-экраны) — переключение по кругу одной кнопкой.
- **Панель «Оформление»** — размер шрифта, межстрочный интервал, поля страницы, абзацный отступ — всё слайдерами.
- **Кнопки прокрутки** (▲/▼) на границе средней и нижней трети экрана, с раздельной скоростью вверх/вниз, плюс кнопка возврата панелей — для чтения одной рукой без свайпов.
- **Озвучка вслух** — Web Speech API с автоопределением языка абзаца для правильного голоса.
- **ИИ-инструменты** (через ключ OpenRouter и/или Groq, вводится самим пользователем и хранится только в его браузере; запрос идёт через relay):
  - 💬 **Комментарий** — литературный/контекстный разбор выделенного отрывка; работает и без второй версии;
  - ❓ **Вопрос по содержанию** — свободный вопрос о прочитанной части (персонаж, событие, деталь), без спойлеров вперёд по сюжету; доступен и как отдельная кнопка в тулбаре выделения (тогда к вопросу прикладывается выделенный отрывок), и в общей панели «Ассистент»;
  - 📄 **Оригинал** — поиск и цитирование соответствующего места во второй версии (если она загружена и открыт режим LINK), с ограничением зоны поиска до ±1 главы;
  - 📝 **Заметка** — свои слова к выделению, без запроса к модели и без ключа;
  - 📖 **Ранее в книге** — короткое напоминание, на чём остановились и что ещё не закрыто. Берётся глава, в которой читатель сейчас, а не вся книга с первой страницы. Сохраняется не сам текст напоминания, а короткий список незакрытого: следующий запуск опирается на него и выкидывает уже разрешённое. Это не растущее саммари.
- **Перевод выделения** — не реализован в самом приложении: системный переводчик Android (контекстное меню при выделении текста) оказался быстрее и качественнее для сценария использования одним человеком, чем любой из опробованных вариантов (MyMemory, Google Translate).
- **PWA:** `manifest.json` + `sw.js` — приложение устанавливается на экран, полностью офлайн-способно после первого запуска онлайн — включая PDF-библиотеку и шрифты, которые раньше не входили в кэш оболочки.
- **Локальные шрифты** (PT Serif, Lora, Inter — лицензия OFL) — без зависимости от Google Fonts CDN.
- **Pinch-zoom работает** — `maximum-scale=1` убран из viewport, важно для читателей, которым нужен жест масштабирования.
- Приватность по умолчанию: ни один файл книги никуда не отправляется, кроме явно выделенного или введённого пользователем текста — и то только в момент запроса к ИИ, вручную инициированного кнопкой. Исключение делает сам читатель: экспорт полки и «Поделиться» уносят полный текст туда, куда он выбрал.

## С ключом и без

Ключ не открывает читалку и не нужен, чтобы ей пользоваться. Это отдельный слой: попросить модель разобрать место.

**Без ключа** работает всё, что не ходит в модель:

- чтение, полка, прогресс, оглавление, поиск, закладки, озвучка, темы, оформление;
- экспорт и импорт полки;
- заметка к выделенному месту — это ваши слова;
- уже оставленные материалы: их можно открыть и перечитать, сеть для этого не нужна.

**С ключом** добавляются четыре запроса:

- комментарий к выделению;
- вопрос по прочитанному;
- «Оригинал» — найти то же место во второй версии;
- «Ранее в книге».

Ответ сам в книгу не записывается. Он остаётся в «Материалах», только если нажать «Оставить здесь».

Ключ вводится в панели «ИИ» и лежит только в браузере. На сервер он уходит в теле конкретного запроса, чтобы relay передал его провайдеру, и на сервере не хранится. В файл полки ключ не попадает. OpenRouter — основной (бесплатные модели, без карты). Groq — запасной. Оба идут через один relay; если relay недоступен, молчат только эти четыре кнопки. Читать, помечать и выгружать полку можно как раньше.

## Стек

- Чистый HTML/CSS/JS, без сборки и фреймворков — всё приложение в одном `index.html`.
- [JSZip](https://stuk.github.io/jszip/) — для `.zip`, `.epub` и `.docx` (все три — ZIP-контейнеры).
- [pdf.js](https://mozilla.github.io/pdf.js/) (Mozilla, legacy-сборка) — для `.pdf`, подключается лениво через динамический `import()` только когда PDF реально открыт.
- Web Speech API (`speechSynthesis`) — озвучка, без внешних сервисов.
- [OpenRouter](https://openrouter.ai/) — основной ИИ-провайдер (бесплатные модели, без VPN из Беларуси, без карты). [Groq](https://groq.com/) (`openai/gpt-oss-120b`) — запасной вариант. Оба доступны через собственный relay-сервер (модуль `link.py` в отдельном Telegram-боте на Render): прямой запрос из браузера упирается в геоблокировку.
- [lucide](https://lucide.dev/) (ISC) — монохромные SVG-иконки интерфейса, встроены инлайн.
- [@fontsource](https://fontsource.org/) (OFL) — локальные шрифты PT Serif/Lora/Inter.
- IndexedDB — «Моя полка»; `localStorage` (с safe-обёрткой на случай приватного режима/`file://`) — настройки, прогресс, закладки, материалы, состояние «Ранее», API-ключи.
- Service Worker — офлайн-кэш оболочки приложения, включая PDF-библиотеку и шрифты (не текста книг).

## Структура проекта

```
index.html              — всё приложение: разметка, стили, вся логика
manifest.json            — PWA-манифест (иконки, цвета, имя)
sw.js                    — service worker: кэш оболочки приложения
jszip.min.js              — библиотека для .zip/.epub/.docx
pdf.min.mjs               — pdf.js (основной модуль)
pdf.worker.min.mjs        — pdf.js (воркер для парсинга PDF)
fonts.css                 — локальные @font-face для PT Serif/Lora/Inter
fonts/                    — сами файлы шрифтов (.woff2/.woff)
icons/                    — иконки PWA (icon-192.png, icon-512.png, icon-maskable-512.png, apple-touch-icon.png)
og-image.png              — превью ссылки для соцсетей (1200×630, Open Graph)
android/twa-manifest.json — конфиг Bubblewrap для Android-обёртки (TWA)
.github/workflows/build-twa.yml — сборка APK в GitHub Actions
```

Все файлы должны лежать рядом, в одной папке — пути в `index.html`/`sw.js`/`manifest.json`/`fonts.css` относительные.

Чтобы мессенджер показал `og-image.png`, в `<head>` нужен абсолютный адрес, не относительный:

```html
<meta property="og:image" content="https://ilsoft-dev.github.io/LINK/og-image.png">
```

**Важно при каждом обновлении `index.html`:** версия кэша (`CACHE_VERSION` в `sw.js`) должна подниматься при любой правке приложения — иначе на устройствах, где LINK уже установлен как PWA, может зависнуть старая закэшированная версия рядом с новой сколь угодно долго (это не гипотетический риск — источник нескольких трудноуловимых багов в истории проекта).

## Как запустить

Готовая версия опубликована на GitHub Pages: https://ilsoft-dev.github.io/LINK/

PWA (service worker, установка на экран) работает только при обслуживании по `http(s)` — на локальном файле (`file://`) браузер не даёт регистрировать service worker, это ожидаемо и некритично: само чтение работает и без него, просто без офлайн-режима и установки на экран.

Варианты хостинга:
- Любой статический хостинг (GitHub Pages, Netlify, Vercel, Cloudflare Pages) — просто выложить содержимое папки как есть.
- Локально для разработки — любой простейший статический сервер (`python3 -m http.server`, `npx serve` и т.п.), открытый по `http://localhost`.

### Android-обёртка (TWA)

Конфиг `android/twa-manifest.json` описывает Trusted Web Activity для адреса `ilsoft-dev.github.io/LINK`. Workflow `build-twa.yml` собирает через Bubblewrap отладочный APK (подпись debug-ключом, генерируется на лету) и выкладывает его артефактом `link-twa-debug-apk`. Запускается вручную (`workflow_dispatch`) или при изменении `twa-manifest.json`/самого workflow. Сгенерированный Android-проект в репозиторий не попадает (см. `.gitignore`).

### ИИ-ключи

Чем сборка с ключом отличается от сборки без него — в разделе «С ключом и без». Коротко: без ключа LINK уже читалка. Ключ нужен только для комментария, вопроса, сверки с оригиналом и «Ранее в книге».

- **OpenRouter** (основной) — `openrouter.ai/keys`, регистрация по email, без карты.
- **Groq** (запасной, через тот же relay) — `console.groq.com`.

Вводится в панели «Ассистент» и хранится только в `localStorage` браузера.

## Известные особенности и ограничения

- **PDF** — не текстовый формат, а «нарисованные» символы с координатами. Реконструкция абзацев эвристическая (кластеризация строк по Y-координате с допуском, разрыв абзаца — по увеличенному межстрочному промежутку). Хорошо работает на простой одноколоночной вёрстке; на сканах без текстового слоя не сработает вообще (нужен OCR — не реализован), на сложной многоколоночной вёрстке текст может перемешаться по порядку строк. Известный баг некоторых PDF-конвертаций (дефис в составном слове превращается в сдвинутый пробел) исправляется только для частых приставок (`non-`, `micro-` и т.п.) — не универсально, нужен был бы словарь языка для полного покрытия.
- **DOCX** — заголовки глав определяются по внутреннему ID стиля (`Heading1`, `Heading2`, ...), который у Word остаётся английским независимо от языка интерфейса — для настоящего Word это надёжно. Для файлов не из Word (LibreOffice, Google Docs) стили могут называться иначе — тогда книга придёт одной главой без заголовка.
- **Relay-сервер** — и OpenRouter, и Groq ходят через один Telegram-бот на Render. Если бот не работает, недоступны все четыре ИИ-запроса сразу. Чтение, заметки и материалы от него не зависят.
- Лимит полки — 15 книг (LRU-вытеснение) — значение по умолчанию, легко меняется в коде (`SHELF_MAX_ENTRIES`), не техническое ограничение IndexedDB.
- Материалы — не больше 80 карточек на книгу, одна карточка на абзац. Второе выделение в том же абзаце не заводит новую карточку: цитату и поле можно заменить только подтверждением.
- «Ранее в книге» не заглядывает в следующую главу и не помнит весь сюжет с первой страницы. Текст самого напоминания между сеансами не хранится — только список незакрытого.
- Поиск находит первое вхождение в абзаце, не все.

## Не реализовано (осознанно)

- Чтение двух версий двумя колонками — связь идёт по отрывку, не по экрану.
- Отдельный файл конспекта помимо экспорта полки. Карточки уезжают вместе с книгой.
- `.mobi`/`.azw` — проприетарный бинарный формат Amazon без нормальных браузерных парсеров.
- `.doc` (старый бинарный Word) — не XML, а бинарный формат; при необходимости — конвертация в `.docx` перед загрузкой.
- OCR для сканированных PDF — отдельная по объёму фича (Tesseract.js и т.п.), добавляется только при реальной необходимости.
- Перевод выделения — сознательно убран из приложения в пользу системного переводчика Android (см. «Возможности»).
